Run SQL against your instance [data lake](/cloud/insights/lake), then save and schedule the reports you want to keep. The **Queries** tab holds that work: **Saved**, **Scheduled**, and **History**.

Insights accepts one read-only DuckDB `SELECT` or `WITH`. Start from a [template](/cloud/insights/templates), or paste your own statement. That rule does not change.

---

## Start a query

Click **New query** to open a blank editor. Set the toolbar date range for the period you care about, then paste a `SELECT` or `WITH` and click **Run**.

<img src="/cloud/img/insights/workbench-new-query.png" alt="Insights workbench after New query, with Untitled lake query and the Queries tab open" className="rounded-lg" />

---

## Accepted SQL queries

Insights accepts **one read-only `SELECT` or `WITH` statement** against the data lake. The dialect is [DuckDB SQL](https://duckdb.org/docs/stable/sql/introduction.html). 

DuckDB functions such as `TRY_CAST`, `DATE_TRUNC`, `ANY_VALUE`, and `BOOL_AND` are available. PostgreSQL-only or MySQL-only syntax is not guaranteed to run. Any other statement is rejected.

| Allowed | Rejected |
| :-- | :-- |
| One `SELECT` or `WITH` | `INSERT`, `UPDATE`, `DELETE`, DDL, `COPY`, `ATTACH`, or multiple statements |
| `transactions`, `balances`, `ledgers`, `identity` | Any other table |
| Named columns | `SELECT *` |

The toolbar date range chooses which days are scanned. A `WHERE` clause can drop rows inside those days. It cannot open days outside the range.

Open [Schema](/cloud/insights/schema) for tables and how they connect. Open [Data Lake](/cloud/insights/lake) for how history is stored.

## Save a query

After you run a query you want to keep, click **Save**. Until you save, the draft is named **Untitled lake query**.

Saved queries live on this instance. Open one from **Saved** to put that SQL back in the editor.

<img src="/cloud/img/insights/run-and-save.gif" alt="Set the date range, run a query, then save it from Actions" className="rounded-lg" />

## Schedule a query

**Schedule query** appears in **Actions** once the query is saved with no unsaved edits.

1. Open **Actions** → **Schedule query**.
2. Pick a **Preset** (Hourly, Daily at 09:00, Weekly on Monday, or Monthly on the 1st). The **Cron expression** field fills from the preset. You can leave it as is unless you need a custom schedule.
3. Confirm **Timezone**, then click **Save schedule**.

Scheduled runs use the saved query and keep a result preview in run history. They do not send external notifications. 

- Schedules always run the **last saved version**. Editor changes do not run until you save again.
- A scheduled report is the same SQL you run by hand. If a run returns empty, check the date range first.

<img src="/cloud/img/insights/schedule-query.gif" alt="Open Actions, choose Schedule query, pick a preset and timezone, then save the schedule" className="rounded-lg" />

## Reopen a past run

Use **History** when you want to reopen SQL you already ran on this instance, including queries you never saved. **Saved** is a different list: it stores the query you chose to keep, while History stores each execution.

<img src="/cloud/img/insights/queries-history.gif" alt="Open History on the Queries tab to reopen a past run" className="rounded-lg" />

## Troubleshooting

<AccordionGroup>
  <Accordion title="My totals do not match the dashboard">
    Check whether the query sums `precise_amount` as-is, or divides by `precision` first. See [Precision](/transactions/precision). 
    
    Also check whether it mixed currencies, or summed `balances.balance` across days. For live data, use the [Ledger API](/reference/get-balance).
  </Accordion>
  <Accordion title="Transaction counts look inflated after a join">
    Check whether `balances`, `ledgers`, or `identity` were collapsed to one row per ID before the join. See [How they connect](/cloud/insights/schema#how-they-connect).
  </Accordion>
  <Accordion title="Open inflight holds look wrong">
    Check the toolbar date range covers both the hold and its commit or void days. You can also reference the [Open inflight holds](/cloud/insights/templates#catching-problems) template.
  </Accordion>
  <Accordion title="Query returns no rows">
    Check the toolbar date range. It has to include the days you expect to see.
  </Accordion>
  <Accordion title="Query fails with a type error">
    A column may be typed differently across days of history. Check whether dates and amounts are wrapped in `TRY_CAST`.
  </Accordion>
  <Accordion title="Query rejected: statement not allowed">
    Check that the statement is one `SELECT` or `WITH`. See [Accepted SQL queries](/cloud/insights/queries#accepted-sql-queries). 
  </Accordion>
  <Accordion title="Query is slow or times out">
    Check the toolbar date range, how many currencies you are scanning, whether you selected `*`, and whether the query has a `LIMIT` (recommended to keep it under 5000).
  </Accordion>
</AccordionGroup>
