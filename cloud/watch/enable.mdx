Enable Watch on a managed Cloud instance to start evaluating ledger transactions against your WatchScript rules.

You need:

- A **managed instance** that is connected
- A **Git repository** with one or more `.ws` rule files
- A **Git token** with read access to the repository (the Enable watch form requires it; for GitHub, use a fine-grained PAT)

---

## Enable from instance details

<Steps>
  <Step title="Open the instance">
    From Cloud home, open `Instances` and select the managed instance where you want Watch enabled.

    The instance details panel opens on the right. Under **Quick Actions**, click `Enable watch`.

    <Frame>
      <img src="/cloud/img/watch/01-open-enable-watch-from-instance.gif" alt="Click an instance, then Enable watch under Quick Actions" className="rounded-lg" />
    </Frame>
  </Step>

  <Step title="Connect your rules repository">
    In the Enable watch panel, fill in the Git Sync fields:

    | Field | Description |
    | :-- | :-- |
    | **Git repository** | HTTPS URL of the repo that contains your `.ws` rule files (for example, `https://github.com/your-org/watch-rules.git`) |
    | **Branch** | Branch Watch should sync (defaults to `main`) |
    | **Git username** | For GitHub HTTPS, use `x-access-token` |
    | **Git token** | A fine-grained personal access token with **Contents: Read-only** on the rules repository |

    The panel also shows Watch add-on pricing (usage-based, per flagged alert). That rate is set by Blnk and is shown before you enable.

    Then click `Enable watch`.

    <Frame>
      <img src="/cloud/img/watch/02-fill-git-sync-form.gif" alt="Fill Git Sync fields on the Enable watch panel" className="rounded-lg" />
    </Frame>
  </Step>

  <Step title="Confirm and enable">
    Cloud shows a confirmation modal with the repository and branch. Click `Confirm and enable`.

    Watch starts deploying on the instance. Deployment status may show `Pending` while provisioning is in progress, then `Running` when Watch is actively monitoring transactions.

    <Frame>
      <img src="/cloud/img/watch/04-confirm-and-enable-watch.gif" alt="Confirm and enable Watch, then wait for Running status" className="rounded-lg" />
    </Frame>
  </Step>
</Steps>

## Enable from Settings

You can also start from Settings:

1. Open your workspace menu and select `Settings`.
2. In the sidebar, open `Watch`.
3. Click `Enable watch` and complete the same Git Sync and confirm steps as above.

<Frame>
  <img src="/cloud/img/watch/03-open-enable-watch-from-settings.gif" alt="Open Settings, go to Watch, then click Enable watch" className="rounded-lg" />
</Frame>

## After Watch is enabled

When deployment completes, the Watch page shows status `Running` ("Actively monitoring transactions"), your configuration (Git repository, branch, and username), and a `Disable watch` action.

<img src="/cloud/img/watch/05-watch-enabled-status.png" alt="Watch settings page showing Running status and configuration" className="rounded-lg" />

Once Watch is running on the instance:

- Transactions on that ledger are evaluated against your synced rules
- Matching rules can produce verdicts and **flagged alerts** in Cloud
- Push updates to your rules repo on the configured branch so Watch can pick up changes on the next sync

For how rules and verdicts work, see:

- [Rule structure](/watch/rules/rule-structure)
- [Setting conditions](/watch/rules/setting-conditions)
- [Defining verdicts](/watch/rules/defining-verdicts)
- [Alerts overview](/cloud/alerts/overview)

## Self-hosted and production license

If you run Watch yourself (outside Cloud managed instances), use the Watch deployment and configuration guides instead of this enable flow.

For production license deployments that bundle Watch, see [License configuration](/cloud/start/license/configuration#watch).
