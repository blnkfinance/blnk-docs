A deployment is a managed Core instance that Blnk hosts and automatically connects to your Cloud workspace. Use this endpoint to create one programmatically. See [Managed instances](/cloud/instances/deploy) to learn more.

<Note>
This endpoint creates managed instances only. For a connected (self-hosted) instance, [connect it from the dashboard](/cloud/instances/create) first.
</Note>

---

<Authorization />

### Body

<RequestExample>
```bash Sandbox wrap
curl -X POST 'https://api.cloud.blnkfinance.com/deployments' \
  -H 'Authorization: Bearer CLOUD_API_KEY' \
  -H 'Content-Type: application/json' \
  -d '{
    "name": "my-sandbox",
    "type": "sandbox"
  }'
```

```bash Production wrap
curl -X POST 'https://api.cloud.blnkfinance.com/deployments' \
  -H 'Authorization: Bearer CLOUD_API_KEY' \
  -H 'Content-Type: application/json' \
  -d '{
    "name": "my-prod",
    "type": "production",
    "region": "nyc3",
    "dedicated": true
  }'
```
</RequestExample>

<ParamField body="name" type="string" required>
Display name for the instance.
</ParamField>

<ParamField body="type" type="string" required>
Deployment type: `sandbox` or `production`. Cloud assigns capacity from this value.
</ParamField>

<ParamField body="region" type="string">
**Production only**. Choose a datacenter closest to your app. Do not send this for sandbox. Cloud assigns the sandbox region.
</ParamField>

<ResponseField name="deployment_id" type="string">
Unique id for this managed deployment (`deploy_...`). Use it with Deployments APIs. Do not pass it as `instance_id` when routing Cloud APIs.
</ResponseField>

<ResponseField name="name" type="string">
Display name of the instance in your workspace.
</ResponseField>

<ResponseField name="type" type="string">
Deployment type: `sandbox` or `production`. Cloud assigns capacity from this value.
</ResponseField>

<ResponseField name="tier" type="string">
Capacity Cloud assigned for this deployment, such as `B1.Micro` or `B1.Standard`. You do not choose this when you create the deployment.
</ResponseField>

<ResponseField name="status" type="string">
`PENDING` until the instance is ready, then `ACTIVE`. Sandbox typically takes 7 - 10 minutes. Production can take 10 - 30 minutes.
</ResponseField>

<ResponseField name="region" type="string">
Datacenter code for the instance. Cloud assigns this for sandbox. You choose it for production.
</ResponseField>

<ResponseField name="dedicated" type="boolean">
`true` when the instance runs on dedicated Production infrastructure. Sandbox is always `false`.
</ResponseField>

<ResponseField name="ingress_mode" type="string">
How Cloud routes traffic to the instance. Live values include `shared` and `legacy`.
</ResponseField>

<ResponseField name="watch_enabled" type="boolean">
Whether Watch is enabled.
</ResponseField>

<ResponseField name="usage_billing_enabled" type="boolean">
Whether usage-based billing is on for the organization.
</ResponseField>

<ResponseField name="usage_billing_enabled_at" type="timestamp">
When usage-based billing was enabled for the organization.
</ResponseField>

<ResponseField name="record_creates_blocked" type="boolean">
`true` when this instance has used its included records and organization usage-based billing is off, so new records cannot be created. `false` while the instance is within its allowance or usage-based billing is on. See [Usage-based billing](/cloud/organization/billing#usage-based-billing).
</ResponseField>

<ResponseField name="created_at" type="timestamp">
When the deployment was created.
</ResponseField>

<ResponseField name="updated_at" type="timestamp">
When the deployment was last updated.
</ResponseField>
