## Sandbox vs Production

Managed instances come in two deployment types: **Sandbox** and **Production**.

Choose between them based on your infrastructure and operational requirements.

### Sandbox

Sandbox provides a shared managed environment for building, testing, and smaller low-risk workloads. It does not include SLA-backed guarantees such as automated backups or high availability.

You can stay on Sandbox as long as it meets your operational and infrastructure requirements.

### Production

Production is designed for teams that require additional operational guarantees and infrastructure control. It includes dedicated infrastructure, high availability, automated backups, dedicated support, and region selection.

Production is not an upgrade path from Sandbox. Choose Production when your operational, reliability, compliance, or support requirements justify dedicated infrastructure. The decision should be based on infrastructure needs, not record volume alone.

### Compare deployment types

Both deployment types include a record allowance. See the [Pricing page](https://blnkfinance.com/pricing) for current rates and plan details.

| Feature | Sandbox | Production |
| --- | --- | --- |
| Best for | Building, testing, and smaller low-risk workloads | Workloads that need operational guarantees |
| Included records | 100,000 | 200,000 |
| Additional usage | `$0.000135` per record | `$0.000175` per record |
| Infrastructure | Shared | Dedicated |
| High availability & backups | No | Yes |
| Region selection | — | Yes |
| Support | Standard | Dedicated Slack and 24/7 SEV 1 response |

<Tip>
  Learn how records are billed in [Usage-based billing](/cloud/organization/billing#usage-based-billing).
</Tip>

To deploy a Sandbox or Production instance, see [Cloud-hosted instances](/cloud/instances/deploy).

## Edit instances

To edit an instance, go the `Settings > Instances`, open its actions list and click `Edit instance`. You can change the name, update the Core URL, or the Core secret key.

### Core URL

- Make sure it is publicly accessible on the internet. If locally hosted, use a tunnel service like ngrok: `ngrok http 5001` to create a public URL.

    <Frame caption="Open the actions list, click Edit instance, and update the Core URL or secret key">
    <img src="/cloud/img/instances/edit-instance-form.gif" alt="Edit instance form showing Core URL and secret key fields" className="rounded-lg" />
    </Frame>

- If hosted on a private network, make sure to whitelist our IP addresses so that Cloud can communicate with your ledger:
  - `161.35.166.95`
  - `161.35.171.250`

### Core secret key

- This is created and set by you in your Blnk configuration.
- Provide the secret key used/created in your config here. If not set, leave empty.

## Remove an instance

To remove an instance, open the actions list and click `Destroy instance` for a managed instance or `Terminate instance` for a self-hosted instance. Follow the instructions in the modal to complete the action. 

Please note that this action is irreversible.
