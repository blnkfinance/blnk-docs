Use `blnk.Transactions.createBulk` to create many [transactions](/transactions/bulk-transactions) in one request (up to **10,000** per request).

<Steps>
<Step title="Call the method">

<Tabs>
<Tab title="Create batch">

```typescript blnk.Transactions.createBulk wrap
const response = await blnk.Transactions.createBulk({
  atomic: true,
  transactions: [
    {
      amount: 1000,
      precision: 100,
      currency: 'USD',
      source: '@source_1',
      destination: '@dest_1',
      reference: 'bulk_001',
      description: 'Payment 1',
    },
    {
      amount: 2000,
      precision: 100,
      currency: 'USD',
      source: '@source_2',
      destination: '@dest_2',
      reference: 'bulk_002',
      description: 'Payment 2',
    },
  ],
});
```

| Field | Type | Description |
| :-- | :-- | :-- |
| `transactions` | `object[]` | Transaction objects to create; up to **10,000** per request. References must be unique within the batch. |
| `atomic` | `boolean` | When `true`, every transaction succeeds or fails together. |
| `inflight` | `boolean` | When `true`, transactions are created in `INFLIGHT` status for a later commit or void. |
| `run_async` | `boolean` | When `true`, Core processes the batch in the background and returns `status: 'queued'`. |
| `skip_queue` | `boolean` | When `true`, transactions bypass the queue and process synchronously. |

</Tab>

<Tab title="Dry run">

Preview the batch without writing anything. `skip_queue` selects cumulative vs independent projection. `run_async` is ignored. See [Dry-run transactions](/transactions/dry-run).

```typescript blnk.Transactions.createBulk wrap {2}
const preview = await blnk.Transactions.createBulk({
  dry_run: true,
  skip_queue: false,
  transactions: [
    {
      precise_amount: 45000,
      precision: 100,
      currency: 'USD',
      source: 'bln_source-bal-001',
      destination: 'bln_dest-bal-001',
      reference: 'ref_payout_450',
      description: 'First payout',
    },
    {
      precise_amount: 10000,
      precision: 100,
      currency: 'USD',
      source: 'bln_source-bal-001',
      destination: 'blnk_dest-bal-002',
      reference: 'ref_payout_100',
      description: 'Second payout',
    },
  ],
});
```

| Field | Type | Description |
| :-- | :-- | :-- |
| `dry_run` | `true` | Return a `BulkTransactionPreview` without creating transactions or consuming references. |
| `skip_queue` | `boolean` | `true` projects items in order against each other. `false` projects each item against current balances on its own. |

Pass `dry_run: true` inline, as shown above, to infer the preview response. If the request is declared separately, type it as `DryRun<BulkTransactions<T>>`.

</Tab>
</Tabs>

</Step>

<Step title="Save the batch ID">

On a posted batch, use `response.data.batch_id` as `parent_transaction` to find child transactions, or with updateStatus to commit or void an inflight batch.

A dry run has no `batch_id`. Check `would_apply` and `results`.

</Step>

<Step title="Response">

<Tabs>
<Tab title="Create batch">

<CodeGroup>
```json Sync wrap
{
  "batch_id": "bulk_c62f200b-905f-4983-a349-cadd279234aa",
  "status": "applied",
  "transaction_count": 4
}
```

```json Async (run_async: true) wrap
{
  "batch_id": "bulk_c62f200b-905f-4983-a349-cadd279234aa",
  "status": "queued",
  "message": "Bulk transaction processing started"
}
```
</CodeGroup>

| Field | Type | Description |
| :-- | :-- | :-- |
| `batch_id` | `string` | Identifier for the batch. Use as parent_transaction to find child transactions, or with updateStatus to commit or void an inflight batch. |
| `status` | `string` | `applied`, `inflight`, or `queued` depending on the batch. |
| `transaction_count` | `number` | Number of transactions when processed synchronously. |
| `message` | `string` | Status message when run_async is true. |

</Tab>
