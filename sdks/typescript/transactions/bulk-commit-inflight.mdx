Use `blnk.Transactions.bulkCommitInflight` to commit multiple inflight transactions.

<Steps>
<Step title="Call the method">

<Tabs>
<Tab title="Queued commit">

```typescript blnk.Transactions.bulkCommitInflight wrap
const response = await blnk.Transactions.bulkCommitInflight({
  transactions: [
    {
      transaction_id: 'txn_c4e70eb8-e4d6-4e04-a2e2-92a43b96',
    },
    {
      transaction_id: 'txn_6164573b-6cc8-45a4-ad2e-7b4ba6a6',
      amount: 40,
    },
    {
      transaction_id: 'txn_0b59f6e6-6c4a-4efa-915c-526f77ef',
      precise_amount: 125034,
    },
  ],
});
```

</Tab>

<Tab title="Synchronous commit">

Pass `skip_queue: true` to process each commit synchronously instead of queuing.

```typescript blnk.Transactions.bulkCommitInflight wrap
const response = await blnk.Transactions.bulkCommitInflight({
  skip_queue: true,
  transactions: [
    {
      transaction_id: 'txn_c4e70eb8-e4d6-4e04-a2e2-92a43b96',
    },
    {
      transaction_id: 'txn_6164573b-6cc8-45a4-ad2e-7b4ba6a6',
      amount: 40,
    },
  ],
});
```

</Tab>

<Tab title="Dry run">

Preview every commit without settling any hold. Items are projected independently. See [Dry-run transactions](/transactions/dry-run).

```typescript blnk.Transactions.bulkCommitInflight wrap {2}
const preview = await blnk.Transactions.bulkCommitInflight({
  dry_run: true,
  transactions: [
    {
      transaction_id: 'txn_c4e70eb8-e4d6-4e04-a2e2-92a43b96',
    },
    {
      transaction_id: 'txn_6164573b-6cc8-45a4-ad2e-7b4ba6a6',
    },
  ],
});
```

| Field | Type | Description |
| :-- | :-- | :-- |
| `dry_run` | `true` | Return a `BulkTransactionPreview` without committing. Holds stay in place. |

Pass `dry_run: true` inline, as shown above, to infer the preview response. If the request is declared separately, type it as `DryRun<BulkCommitInflightRequest>`.

</Tab>
</Tabs>

| Field | Type | Description |
| :-- | :-- | :-- |
| `transactions` | `object[]` | Up to 100 inflight transactions to commit. |
| `transactions[].transaction_id` | `string` | Inflight transaction ID to commit. |
| `transactions[].amount` | `number` | Partial commit amount. Omit to commit the full remaining inflight amount. |
| `transactions[].precise_amount` | `number` | Precision-applied partial commit amount. Takes precedence over amount. |
| `skip_queue` | `boolean` | When `true`, process synchronously instead of queuing. |

</Step>

<Step title="Review per-item results">

On a posted batch, check `response.data.results` for each transaction's outcome. Failed items include a code and message without stopping the rest of the batch.

A dry run has no `succeeded` / `failed` counts. Check `would_apply` and `results`.

</Step>

<Step title="Response">

<Tabs>
<Tab title="Queued commit">

```json 200 OK wrap expandable
{
  "succeeded": 2,
  "failed": 1,
  "results": [
    {
      "transaction_id": "txn_c4e70eb8-e4d6-4e04-a2e2-92a43b96",
      "status": "succeeded"
    },
    {
      "transaction_id": "txn_6164573b-6cc8-45a4-ad2e-7b4ba6a6",
      "status": "succeeded"
    },
    {
      "transaction_id": "txn_0b59f6e6-6c4a-4efa-915c-526f77ef",
      "status": "failed",
      "code": "INVALID_AMOUNT",
      "message": "cannot commit more than inflight amount"
    }
  ]
}
```

| Field | Type | Description |
| :-- | :-- | :-- |
| `succeeded` | `number` | Number committed successfully. |
| `failed` | `number` | Number that failed. |
| `results` | `object[]` | Per-transaction outcome in request order. |
| `results[].status` | `string` | `succeeded` or `failed`. |
| `results[].code` | `string` | Failure code (for example `NOT_FOUND`, `ALREADY_VOIDED`, `INVALID_AMOUNT`). |
| `results[].message` | `string` | Human-readable failure message. |

</Tab>

<Tab title="Dry run">
