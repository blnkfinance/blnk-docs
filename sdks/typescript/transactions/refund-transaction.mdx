Use `blnk.Transactions.refund` to refund a transaction.

<Steps>
<Step title="Call the method">

<Tabs>
<Tab title="Queued refund">

Omit the optional body to queue the refund using Core defaults. See [Refunds](/transactions/refunds).

```typescript blnk.Transactions.refund wrap
const response = await blnk.Transactions.refund(
  'txn_c4e70eb8-e4d6-4e04-a2e2-92a43b969e0c',
);
```

| Field | Type | Description |
| :-- | :-- | :-- |
| `transactionId` | `string` | Transaction ID of the applied transaction to refund. |

</Tab>

<Tab title="Skip queue">

Process the refund synchronously instead of queuing.

```typescript blnk.Transactions.refund wrap {4}
const response = await blnk.Transactions.refund(
  'txn_c4e70eb8-e4d6-4e04-a2e2-92a43b969e0c',
  {
    skip_queue: true,
  },
);
```

| Field | Type | Description |
| :-- | :-- | :-- |
| `skip_queue` | `boolean` | When `true`, process the refund synchronously instead of queuing. |

</Tab>

<Tab title="Description and metadata">

Set a narration and merge metadata onto the copy inherited from the original. See [Refunds](/transactions/refunds#description-and-metadata).

```typescript blnk.Transactions.refund wrap {4-9}
const response = await blnk.Transactions.refund(
  'txn_c4e70eb8-e4d6-4e04-a2e2-92a43b969e0c',
  {
    description: 'Refund for ticket #4821',
    meta_data: {
      type: 'refund',
      reason: 'goodwill',
    },
  },
);
```

| Field | Type | Description |
| :-- | :-- | :-- |
| `description` | `string` | Narration for the refund. When omitted or empty, the refund copies the original. |
| `meta_data` | `Record<string, unknown>` | Merged onto metadata inherited from the original. Keys you send replace matching keys. |

</Tab>

<Tab title="Dry run">

Preview the refund without writing anything. See [Dry-run transactions](/transactions/dry-run).

```typescript blnk.Transactions.refund wrap {4}
const preview = await blnk.Transactions.refund(
  'txn_c4e70eb8-e4d6-4e04-a2e2-92a43b969e0c',
  {
    dry_run: true,
  },
);
```

| Field | Type | Description |
| :-- | :-- | :-- |
| `dry_run` | `true` | Return a `TransactionPreview` without creating a refund or consuming a reference. |

</Tab>
</Tabs>

</Step>

<Step title="Save the refund transaction ID">

On a posted refund, use `response.data.transaction_id` to track it. Check `parent_transaction` to confirm it links to the original.

A dry run has no `transaction_id`. Check `would_apply` instead.

</Step>

| Field | Type | Description |
| :-- | :-- | :-- |
| `transaction_id` | `string` | ID of the new refund transaction. Omitted on a dry run. |
| `parent_transaction` | `string` | Original transaction being refunded. |
| `source` | `string` | Original destination, now the source of the refund. |
| `destination` | `string` | Original source, now the destination of the refund. |
| `status` | `string` | Status of the refund transaction. |
