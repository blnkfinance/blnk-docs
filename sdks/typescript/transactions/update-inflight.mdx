Use `blnk.Transactions.updateStatus` to commit or void an [inflight](/transactions/inflight) transaction or batch.

<Steps>
<Step title="Call the method">

<Tabs>
<Tab title="Commit">

```typescript blnk.Transactions.updateStatus wrap
const response = await blnk.Transactions.updateStatus(
  'txn_c4e70eb8-e4d6-4e04-a2e2-92a43b969e0c',
  {
    status: 'commit',
  },
);
```

</Tab>

<Tab title="Partial commit">

```typescript blnk.Transactions.updateStatus wrap
const response = await blnk.Transactions.updateStatus(
  'txn_c4e70eb8-e4d6-4e04-a2e2-92a43b969e0c',
  {
    status: 'commit',
    amount: 500
  },
);
```

</Tab>

<Tab title="Void">

```typescript blnk.Transactions.updateStatus wrap
const response = await blnk.Transactions.updateStatus(
  'txn_c4e70eb8-e4d6-4e04-a2e2-92a43b969e0c',
  {
    status: 'void',
  },
);
```

</Tab>

<Tab title="Dry run">

Preview the commit or void without settling the hold. See [Dry-run transactions](/transactions/dry-run).

```typescript blnk.Transactions.updateStatus wrap {5}
const preview = await blnk.Transactions.updateStatus(
  'txn_c4e70eb8-e4d6-4e04-a2e2-92a43b969e0c',
  {
    status: 'commit',
    dry_run: true,
  },
);
```

| Field | Type | Description |
| :-- | :-- | :-- |
| `dry_run` | `true` | Return a `TransactionPreview` without committing or voiding. The inflight hold stays in place. |

Pass `dry_run: true` inline, as shown above, to infer the preview response. If the request is declared separately, type it as `DryRun<UpdateTransactionStatus<T>>`.

</Tab>
</Tabs>

| Field | Type | Description |
| :-- | :-- | :-- |
| `transactionOrBatchId` | `string` | Inflight transaction ID, or batch ID from createBulk. |
| `status` | `string` | `commit` to apply funds, or `void` to cancel and roll back. |
| `amount` | `number` | Partial commit amount. See [Partial commits](/transactions/inflight#partial-commits). |
| `precise_amount` | `number` | Precision-applied partial commit amount. Takes precedence over amount. |

</Step>

<Step title="Confirm the outcome">

On a posted update, check `response.data.status` for `APPLIED` or `VOID`. The child gets a new `transaction_id`. Use `parent_transaction` to link it to the original inflight transaction.

A dry run has no `transaction_id`. Check `would_apply` instead.

</Step>
