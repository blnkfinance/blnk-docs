Use `blnk.transactions.refund` to refund a transaction.

<Steps>
<Step title="Call the method">

<Tabs>
<Tab title="Queued refund">

Omit the optional body to queue the refund using Core defaults. See [Refunds](/transactions/refunds).

```python blnk.transactions.refund wrap
response = blnk.transactions.refund(
  "txn_c4e70eb8-e4d6-4e04-a2e2-92a43b969e0c",
)
```

</Tab>

<Tab title="Skip queue">

Process the refund synchronously instead of queuing.

```python blnk.transactions.refund wrap {3}
response = blnk.transactions.refund(
  "txn_c4e70eb8-e4d6-4e04-a2e2-92a43b969e0c",
  {"skip_queue": True},
)
```

</Tab>

<Tab title="Description and metadata">

Set a narration and merge metadata onto the copy inherited from the original. See [Refunds](/transactions/refunds).

```python blnk.transactions.refund wrap {3-8}
response = blnk.transactions.refund(
  "txn_c4e70eb8-e4d6-4e04-a2e2-92a43b969e0c",
  {
    "description": "Refund for ticket #4821",
    "meta_data": {
      "type": "refund",
      "reason": "goodwill",
    },
  },
)
```

</Tab>

<Tab title="Dry run">

Preview the refund without writing anything. See [Dry-run transactions](/transactions/dry-run).

```python blnk.transactions.refund wrap {3}
preview = blnk.transactions.refund(
  "txn_c4e70eb8-e4d6-4e04-a2e2-92a43b969e0c",
  {"dry_run": True},
)
```

</Tab>
</Tabs>

| Field | Type | Description |
| :-- | :-- | :-- |
| `transactionId` | `str` | Transaction ID of the applied transaction to refund. |
| `skip_queue` | `bool` | When `True`, process the refund synchronously instead of queuing. |
| `description` | `str` | Narration for the refund. When omitted or empty, the refund copies the original. |
| `meta_data` | `dict` | Merged onto metadata inherited from the original. |
| `dry_run` | `bool` | Return a preview without creating a refund. |

</Step>

<Step title="Save the refund transaction ID">

On a posted refund, use `response.data["transaction_id"]` to track it. Check `parent_transaction` to confirm it links to the original.

A dry run has no `transaction_id`. Check `would_apply` instead.

</Step>

| Field | Type | Description |
| :-- | :-- | :-- |
| `transaction_id` | `str` | ID of the new refund transaction. |
| `parent_transaction` | `str` | Original transaction being refunded. |
| `source` | `str` | Original destination, now the source of the refund. |
| `destination` | `str` | Original source, now the destination of the refund. |
| `status` | `str` | Status of the refund transaction. |

</Step>
