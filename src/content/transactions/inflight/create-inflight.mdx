<Version>Available in version 0.6.0 and later.</Version>

An inflight transaction reserves funds until you [commit](/transactions/inflight/commit-inflight) or [void](/transactions/inflight/void-inflight) it. When you set `inflight: true`, Blnk tracks the pending amount on inflight fields. The main balance amount does not move yet.

Use inflight when you need authorization, verification, or external confirmation before applying a transfer.

## Use cases

Useful applications for `inflight` include:

- **KYC limits:** Hold deposits inflight until the user's KYC tier is updated.
- **[Escrow](/tutorials/quick-start/escrow-payments):** Show users an amount being held without making it spendable.
- **Card payouts:** Hold funds until the payment processor authorizes the charge.
- **External payouts:** Hold funds while a provider processes the payout; commit or void based on the outcome.

## How it works

<span id="inflight-balance-tracking" />

The main balance amount does not move yet.

Blnk records the pending amount on three fields: `inflight_debit_balance` (reserved to leave), `inflight_credit_balance` (pending in), and `inflight_balance` (credit minus debit).

For example, \$100 is held from `balance_A` to `balance_B`. `balance_A` starts at \$200. `balance_B` starts at \$0.

| `balance_id` | **Main balance** | **Inflight balance** | **Inflight credit** | **Inflight debit** |
| :-- | :-- | :-- | :-- | :-- |
| `balance_A` | 200 | -100 | 0 | 100 |
| `balance_B` | 0 | 100 | 100 | 0 |

`balance_A` can still spend up to \$100 (`balance - inflight_debit_balance`). `balance_B` shows \$100 incoming, and that amount is not spendable.

[Commit](/transactions/inflight/commit-inflight) moves the \$100 into the main balances. [Void](/transactions/inflight/void-inflight) drops the inflight amounts and leaves the main balances at 200 and 0.

## Record one inflight transaction

<Tabs>
<Tab title="Using the API">

<Steps>
<Step title="Create an inflight transaction">

Set `inflight: true` on a [Create transaction](/reference/create-transaction) request:

<CodeGroup>
```bash cURL wrap {12}
curl -X POST "http://YOUR_BLNK_INSTANCE_URL/transactions" \
  -H "X-blnk-key: <api-key>" \
  -H "Content-Type: application/json" \
  -d '{
    "precise_amount": 10000,
    "precision": 100,
    "reference": "ref_001adcfgf",
    "currency": "USD",
    "source": "bln_28edb3e5-c168-4127-a1c4-16274e7a28d3",
    "destination": "bln_ebcd230f-6265-4d4a-a4ca-45974c47f746",
    "description": "For vacation",
    "inflight": true
  }'
```

```typescript TypeScript wrap {9}
const response = await blnk.Transactions.create({
  precise_amount: 10000,
  precision: 100,
  reference: 'ref_001adcfgf',
  currency: 'USD',
  source: 'bln_28edb3e5-c168-4127-a1c4-16274e7a28d3',
  destination: 'bln_ebcd230f-6265-4d4a-a4ca-45974c47f746',
  description: 'For vacation',
  inflight: true,
});
```

```go Go wrap {11}
transaction, resp, err := client.Transaction.Create(blnkgo.CreateTransactionRequest{
    ParentTransaction: blnkgo.ParentTransaction{
        PreciseAmount: big.NewInt(10000),
        Reference: "ref_001adcfgf",

        Precision: 100,

        Destination: "bln_ebcd230f-6265-4d4a-a4ca-45974c47f746",
        Description: "For vacation",
    },
    Inflight: true,

```

## Record split inflight transaction

A split inflight is a [split transaction](/transactions/split-transactions) with `inflight` set to `true`. 

Several sources pay one destination, or one source pays several destinations, and each leg stays on hold.

<Steps>
<Step title="Record the split">

Call [Create transaction](/reference/create-transaction) with `inflight: true` and one side of the split. This example pays three destinations from Sarah's balance.

<CodeGroup>
```bash cURL wrap {11}

  -H "X-blnk-key: <api-key>" \

  -d '{
    "precise_amount": 3000000,
    "precision": 100,

    "currency": "USD",
```

## Record bulk inflight transaction

<Version>Available in version 0.9.0 and later.</Version>

A [bulk transaction](/transactions/bulk-transactions) records many transfers in one request. Each object in `transactions` is its own transfer. The batch shape, `atomic`, and `run_async` stay on that page.

<Steps>
<Step title="Record the batch">

Set `inflight: true` on the [bulk request](/reference/bulk-transactions), not on each child. Blnk ignores an `inflight` flag inside `transactions` and holds every transfer in the batch.

<CodeGroup>
```bash cURL wrap {5}
curl -X POST "http://YOUR_BLNK_INSTANCE_URL/transactions/bulk" \
  -H "X-blnk-key: <api-key>" \
  -H "Content-Type: application/json" \
  -d '{
    "inflight": true,
    "transactions": [
      {
        "precise_amount": 10000,
        "precision": 100,
        "reference": "tx_003",
        "description": "First transaction",
        "currency": "NGN",
        "source": "@account1",
        "destination": "@account2"
      },
      {
        "precise_amount": 5000,
        "precision": 100,
        "reference": "tx_004",
        "description": "Second transaction",
        "currency": "NGN",
        "source": "@account2",
        "destination": "@account3"
      }
    ]
  }'
```

## Error handling

<Version>Structured errors are available from Blnk Core 0.15.0 and later.</Version>

Create transaction returns `400` when the request body fails validation before Blnk records an inflight transaction.

| Code | When it happens |
| :-- | :-- |
| `TXN_VALIDATION_ERROR` | Required fields are missing or invalid (for example both `amount` and `precise_amount`). |
| `GEN_MALFORMED_REQUEST` | The JSON body is malformed or exceeds the JSON request size limit. Oversized reconciliation file uploads return `413 GEN_PAYLOAD_TOO_LARGE`. |

```json 400 Bad Request wrap
{
  "error_detail": {
    "code": "TXN_VALIDATION_ERROR",
    "message": "amount: cannot be blank."
  },
  "errors": "amount: cannot be blank."
}
```

To resolve the error:

| Code | What to do |
| :-- | :-- |
| `TXN_VALIDATION_ERROR` | Fix the field named in the error message. See [Create transaction](/reference/create-transaction). |
| `GEN_MALFORMED_REQUEST` | Check JSON syntax and request size limits in [Server security](/advanced/configuration/server-security). |

When the source balance has insufficient funds, the result depends on whether you used the queue. See [Managing insufficient funds](/transactions/introduction#managing-insufficient-funds).

Commit and void errors are covered on [Commit inflight transactions](/transactions/inflight/commit-inflight#error-handling) and [Void inflight transactions](/transactions/inflight/void-inflight#error-handling). 

See [API error codes](/advanced/error-codes) for the full catalogue.
