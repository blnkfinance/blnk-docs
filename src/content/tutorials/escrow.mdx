An escrow payment is money a buyer sends to a seller that stays on hold until the sale is done. A commit releases it to the seller, and a void returns it to the buyer.

This tutorial shows how to implement that with Blnk.

<TutorialSteps>
  <TutorialStep title="Design the money movement">
    Before we start building, we need to define our [money movement](/ledgers/money-movement-map). This helps us outline how money moves from Alice to Bob.

    Alice is buying from Bob, and the payment stays on hold until the sale is done. She sends \$100.00 from her balance to his.

    The transaction is [inflight](/transactions/inflight/create-inflight), so neither balance changes until we commit or void it. A commit applies the \$100.00 to Bob, and a void drops the hold and leaves the money with Alice.

  <TutorialStep title="Create a ledger">
    Before we start recording transactions, we need to set up our [ledger](/ledgers/introduction) to track the buyer, the seller, and their balances.

    For our escrow example, we only support one currency, USD. Therefore, we'll create a ledger to manage all USD balances belonging to our customers.

    Create the ledger:

<TutorialCode>
<CodeGroup>

```bash cURL wrap
curl -X POST "{{CORE_URL}}/ledgers" \
  -H "X-blnk-key: {{CORE_SECRET_KEY}}" \
  -H "Content-Type: application/json" \
  -d '{
    "name": "{{name}}",
    "meta_data": {
      "description": "{{description}}"
    }
  }'
```

```typescript TypeScript wrap
const response = await blnk.Ledgers.create({

  },

```

  <TutorialStep title="Record a deposit">
    Alice deposits \$100.00 via an ACH transfer so she can pay Bob. The destination is her balance, and the source is `@WorldUSD_ACH`.

    The amount is a decimal, and we multiply it by [precision](/transactions/precision) `100` to get `precise_amount`. The reference and the description are already set.

    <Note>
      To make sure the transaction applies, we need to turn on [overdraft](/transactions/overdrafts). Without it, `@WorldUSD_ACH` is created with a 0 balance, and Blnk would reject the record because the source has insufficient funds.
    </Note>

    Record the deposit:

<CodeGroup>

```bash cURL wrap
curl -X POST "{{CORE_URL}}/transactions" \
  -H "X-blnk-key: {{CORE_SECRET_KEY}}" \
  -H "Content-Type: application/json" \
  -d '{
    "precise_amount": {{precise_amount}},
    "precision": 100,
    "reference": "DEP-20261019-103000",
    "description": "ACH deposit",
    "currency": "{{currency}}",
    "source": "{{source}}",
    "destination": "{{destination}}",
    "allow_overdraft": true
  }'
```

```typescript TypeScript wrap
const amount = {{amount}};
const precision = 100;
const precise_amount = Math.round(amount * precision);
```

  <TutorialStep title="Commit the hold">
    The sale is done, so we [commit](/transactions/inflight/commit-inflight) the hold. We send `commit` for the transaction from the previous step, and the \$100.00 moves from Alice to Bob.

    <Note>
      Blnk queues the commit. The response stays `INFLIGHT` until the worker applies it, and then Bob's balance shows the \$100.00.
    </Note>

    <Tip>
      If the sale falls through, [void](/transactions/inflight/void-inflight) the hold instead, and Alice keeps the \$100.00. To release part of it, commit a `precise_amount`, and the rest stays inflight.
    </Tip>

    Commit the hold:

<CodeGroup>

```bash cURL wrap
curl -X PUT "{{CORE_URL}}/transactions/inflight/{{transaction_id}}" \
  -H "X-blnk-key: {{CORE_SECRET_KEY}}" \
  -H "Content-Type: application/json" \
  -d '{
    "status": "commit"
  }'
```

```typescript TypeScript wrap
const response = await blnk.Transactions.updateStatus(
  '{{transaction_id}}',
  {
    status: 'commit',
  },
);
```

```go Go wrap
transaction, _, _ := client.Transaction.Update(
    "{{transaction_id}}",
    blnkgo.UpdateStatus{
        Status: blnkgo.InflightStatusCommit,
    },
)
```

