Use connection commands to create or confirm your connection with your Blnk Core instance before you run resource commands.

## `blnk connect`

Point the CLI at Core, store your API key locally, and confirm the instance responds. Run this after install or whenever you switch environments. Use a Core URL for direct connect, or `--cloud` with an `instance_…` id when Blnk hosts the instance on Cloud.

```bash blnk connect
blnk connect [url] [options]
```

<SectionLabel icon="brackets">Arguments</SectionLabel>

| Argument | Type | Required | Description |
| :-- | :-- | :-- | :-- |
| `url` | string | No | Core base URL for direct connect, including `http://` or `https://`. Not used with `--cloud`. |

<SectionLabel icon="settings-2">Options</SectionLabel>

| Option | Type | Description |
| :-- | :-- | :-- |
| `--cloud` | boolean | Connect through the Blnk Cloud Enterprise proxy. |
| `--instance-id` | string | Cloud instance id (`instance_…`). Required with `--cloud`. |
| `--api-key` | string | API key without a prompt (workspace key for `--cloud`, Core key for direct). |
| `-h, --help` | boolean | Show help for this command. |

<SectionLabel icon="list-ordered">Usage</SectionLabel>

<Steps>
<Step title="Direct Core (local or self-hosted)">
Pass the Core URL, or leave it off and answer the prompts. At `api key >`, use the **Core** secret for that instance.

```bash Direct connect
blnk connect http://localhost:5001
```

```text 200 Success icon="check-circle"
success:
  Successfully connected to "http://localhost:5001"
```
</Step>
<Step title="Blnk Cloud (managed instance)">
On a managed instance, do not run `blnk connect` against the deployment URL with the workspace key from [Settings → API keys](https://cloud.blnkfinance.com/cloud/settings/api-keys). That key is for the Cloud API, not direct Core auth on the deployment hostname.

Instead, pass `--cloud` and the instance id from **Copy instance ID** in the Cloud dashboard. The CLI calls `https://api.cloud.blnkfinance.com/proxy/...` with your workspace key and routes the request to your instance. Resource commands such as `ledgers list` and `transactions create` use that path automatically.

```bash Cloud proxy connect
blnk connect --cloud --instance-id instance_abc123
```

```text Prompts wrap
api key >
```

```text 200 Success icon="check-circle"
success:
  Connected to Blnk Cloud proxy for "instance_abc123" at https://api.cloud.blnkfinance.com
```
</Step>
<Step title="Errors">
<CodeGroup>
```text Invalid API key icon="close-circle" wrap
error:
  Invalid API key. Verify that the provided API key is correct and try again.
```
```text Cloud workspace key icon="close-circle" wrap
error:
  Invalid workspace API key. Create one under Cloud Settings > API keys and try again.
```
```text Instance unreachable icon="close-circle" wrap
error:
  Can't connect to instance. Verify the URL and ensure your instance is running.
```
</CodeGroup>
</Step>
</Steps>

## `blnk info`

See how you are connected and whether the last health check succeeded.

```bash blnk info
blnk info
```

<SectionLabel icon="settings-2">Options</SectionLabel>

| Option | Type | Description |
| :-- | :-- | :-- |
| `-h, --help` | boolean | Show help for this command. |

<SectionLabel icon="list-ordered">Usage</SectionLabel>

<Steps>
<Step title="Check connection status">
```bash Check the connection wrap
blnk info
```

<CodeGroup>
```text Direct Core icon="check-circle"
Current server connection:
  http://localhost:5001 [+] connected
```
```text Cloud proxy icon="check-circle"
Current server connection:
  https://api.cloud.blnkfinance.com (instance instance_abc123) [+] connected
  mode: Blnk Cloud proxy
```
```text Not connected icon="close-circle" wrap
Current server connection:
  Not set [-] not connected
```
</CodeGroup>
</Step>
</Steps>
