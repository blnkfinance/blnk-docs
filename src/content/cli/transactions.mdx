Use the `transactions` command to list transfers, inspect a single post, create transactions, and commit, void, or refund inflight work. Reach for this command when you are debugging money movement or testing a flow on Core.

| Command | Alias | Description |
| :-- | :-- | :-- |
| list | l | Browse transfers with filters; add `--id` for one transaction |
| create | c | Post a transfer with flags, or prompts when no field flags are passed |
| update | u | Commit, void, or refund an existing transaction |
| bulk | | Create, commit, or void many transactions from a JSON file |
| queue recover | | Re-enqueue queued transactions older than a threshold |

## `list`

Monitor money movement in a paginated table with amount, currency, status, and related IDs. Filter by `--status`, `--currency`, or `--balance-id` to audit queued work, applied posts, or activity on one account.

```bash blnk transactions list
blnk transactions list [options]
```

<SectionLabel icon="settings-2">Options</SectionLabel>

| Option | Type | Default | Description |
| :-- | :-- | :-- | :-- |
| `--{field}` | string | - | Filter by any indexed field (for example `--status APPLIED`, `--currency "USD,EUR"`). |
| `-p, --page` | integer | `1` | Page number. |
| `--per-page` | integer | `10` | Results per page. |
| `--json` | boolean | - | Print the Core response as JSON instead of the table. |
| `-h, --help` | boolean | - | Show help for this command. |

## `list --id`

Inspect one transaction end to end: source, destination, reference, status, and metadata. Pass `--json` when you need precision, inflight flags, or parent/child links exactly as Core returns them.

```bash blnk transactions list --id
blnk transactions list --id <transaction-id> [options]
```

<SectionLabel icon="settings-2">Options</SectionLabel>

| Option | Type | Required | Description |
| :-- | :-- | :-- | :-- |
| `--id` | string | Yes | Transaction ID to fetch (for example `txn_fa19841f-faa5-4838-9295-b7278a4ff71d`). |
| `--json` | boolean | No | Print the full API object as JSON instead of a formatted summary. |
| `-h, --help` | boolean | No | Show help for this command. |

<SectionLabel icon="list-ordered">Usage</SectionLabel>


## `create`

Post a transfer between balances or indicators through prompts for amount, precision, parties, reference, and inflight options, or pass those same values as flags. Handy for a quick test on Core. For many transfers at once, use bulk.

```bash blnk transactions create
blnk transactions create [options]
```

<SectionLabel icon="brackets">Arguments</SectionLabel>

Pass these as flags, or leave them off and answer the prompts. If you pass any flag and omit a required one, the CLI stops and names the missing flag.

| Argument | Type | Required | Description |
| :-- | :-- | :-- | :-- |
| `amount` | string | Yes | Transaction amount. Flag: `--amount`. Prompt: `amount >` |
| `precision` | integer | Yes | Amount precision (for example `100` for cents). Flag: `--precision`. Prompt: `precision >` |
| `currency` | string | Yes | Currency code. Flag: `--currency`. Prompt: `currency >` |
| `source` | string | Yes | Source balance ID or indicator. Flag: `--source`. Prompt: `source >` |
| `destination` | string | Yes | Destination balance ID or indicator. Flag: `--destination`. Prompt: `destination >` |
| `reference` | string | Yes | Unique reference. Flag: `--reference`. Prompt: `reference >` |
| `description` | string | Yes | Short description. Flag: `--description`. Prompt: `description >` |
| `allow_overdraft` | boolean | No | Allow a negative source balance. Flag: `--allow-overdraft`. Prompt: `allow overdraft >` |
| `inflight` | boolean | No | Hold the transfer until you commit or void it. Flag: `--inflight`. Prompt: `inflight >` |
| `meta_data` | object | No | Metadata as JSON. Flag: `--metadata`. Prompt: `metadata (json) >`. Press **Enter** to skip. |

<SectionLabel icon="settings-2">Options</SectionLabel>

| Option | Type | Description |
| :-- | :-- | :-- |
| `--scheduled-for` | string | When to apply the transfer, for example `2026-12-01T10:00:00Z`. |
| `--dry-run` | boolean | Preview the transfer without writing it. |
| `--json` | boolean | After a successful create, print the full API response as JSON. |
| `-h, --help` | boolean | Show help for this command. |

<SectionLabel icon="list-ordered">Usage</SectionLabel>

<Steps>
<Step title="Create a transaction">
Pass the fields on the command line:

```bash Create a transaction
blnk transactions create \
  --amount 10 \
  --precision 100 \
  --currency USD \
  --source @WorldUSD \
  --destination @Customer \
  --reference ref_001 \
  --description "Test transfer" \
  --allow-overdraft \
  --dry-run \
  --json
```

```bash Schedule a transaction

  --source @WorldUSD \
  --destination @Customer \
  --reference ref_002 \
  --description "Scheduled transfer" \
  --allow-overdraft \
  --scheduled-for 2026-12-01T10:00:00Z \
  --json
```
</Step>

## `update`

Move an existing transaction through its lifecycle: commit inflight funds, void before settlement, or refund after apply. Supply the transaction ID and exactly one of `--commit`, `--void`, or `--refund`.

```bash blnk transactions update
blnk transactions update [options] <transaction-id>
```

<SectionLabel icon="brackets">Arguments</SectionLabel>

| Argument | Type | Required | Description |
| :-- | :-- | :-- | :-- |
| `transaction-id` | string | Yes | Transaction ID to update (for example `txn_6164573b-6cc8-45a4-ad2e-7b4ba6a60f7d`). |

<SectionLabel icon="settings-2">Options</SectionLabel>

| Option | Type | Description |
| :-- | :-- | :-- |
| `--commit` | boolean | Fully commit an inflight transaction. |
| `--void` | boolean | Void an inflight transaction. |
| `--refund` | boolean | Refund a transaction. |
| `--json` | boolean | Print the Core response as JSON. |
| `-h, --help` | boolean | Show help for this command. |

<SectionLabel icon="list-ordered">Usage</SectionLabel>

<Steps>
<Step title="Commit a transaction">
Run the command with `--commit` and an inflight transaction ID:

## `bulk`

Use bulk when one file holds many transfers, or when you need to commit or void several inflight holds together. Each command takes `--input`. Add `--dry-run` to preview, and `--json` to print the Core response.

| Subcommand | Description |
| :-- | :-- |
| `create` | Post the transfers in the file |
| `commit` | Commit the inflight holds in the file |
| `void` | Void the inflight holds in the file |

```bash Bulk create wrap
blnk transactions bulk create --input batch.json --dry-run --json
```

```bash Bulk commit and void wrap
blnk transactions bulk commit --input commit.json --skip-queue --json
blnk transactions bulk void --input void.json --skip-queue --json
```

Commit input is `{ "transactions": [{ "transaction_id": "txn_…" }] }`. Void input is `{ "transaction_ids": ["txn_…"] }`.

## `queue recover`

Use this when transfers have stayed queued longer than you expect. `--threshold` is how old they must be, for example `5m` or `1h`. Leave it off and the CLI uses two minutes. A recovered count of zero means nothing was waiting that long.

```bash Recover the queue wrap
blnk transactions queue recover --threshold 5m --json
```

```text JSON icon="check-circle"
Queue recovery:
{
  "recovered": 0,
  "threshold": "5m0s"
}
```
