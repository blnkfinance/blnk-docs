A ledger records every movement of value as a balanced entry. This page is a specimen for how a guide should read: sections separated by space, with no rule above each heading.

The first paragraphs sit close to the title. A new section starts only when the heading has enough room above it to mark the break.

## Open a ledger

Create one ledger for each book of record. A customer wallet, an internal float, and a settlement account can share a ledger when they belong to the same book, or live apart when they do not.

Give the ledger a name your operators will recognize. The name is a label. The identifier is what later calls use.

### Name and currency

Pick the currency before the first balance is created. Balances on that ledger post in that currency, and a later change does not rewrite history.

Keep the name short. "Customer wallets" is easier to scan than a sentence that restates the product.

### Who can post

Only services that record movement should post to the ledger. A read-only report can query it. It should not create entries of its own.

## Record a movement

A movement takes value from one balance and puts the same value on another. The two sides are written together. If one side fails, neither side is kept.

Use a reference your system already has, such as a payment id or a transfer id. That reference is how you find the entry again without storing a second copy of the amount.

- Debit the source balance.
- Credit the destination balance.
- Store the external reference on the entry.

When the amount is large enough to need a breakdown, split it into lines rather than into separate movements:

1. Confirm the source can cover the full amount.
2. Post the principal.
3. Post the fee to the fee balance in the same entry.

## Read it back

After the entry is stored, read the balances that changed. The source is lower by the amount. The destination is higher by the same amount. The ledger total is unchanged.

Inline `transaction_id` values use Geist Mono, as do fenced blocks:

```txt
source        -125.00
destination   +125.00
ledger total    0.00
```

A second paragraph under the sample should sit at the same distance as any other paragraph, not tighter because a block came before it.

## Close the day

At the end of the day, snapshot the balances you report on. The snapshot is a copy of those balances at a time. It does not replace the entries that produced them.

### What to include

Include every balance a regulator or a finance owner will ask for. Leave out balances that exist only to stage a movement still in progress.

### What to leave

Leave the raw entries in place. A snapshot that deletes the entries it summarizes cannot be checked later.

## When something fails

If a post is rejected, show the reason and leave both balances as they were. Do not write a compensating entry for a movement that never landed.

Retry only when the reference is the same and the previous attempt did not commit. A new reference is a new movement, even when the amount matches.
