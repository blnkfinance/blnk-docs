Configure object-storage persistence for your Monitoring service.

When set, Monitoring stores traces, metrics, and logs captured from connected instances in your configured S3-compatible bucket so they can be retained and retrieved outside the control-plane database.

```dotenv .env wrap
MONITORING_STORAGE_S3_BUCKET=
MONITORING_STORAGE_S3_ENDPOINT=
MONITORING_STORAGE_S3_ACCESS_KEY_ID=
MONITORING_STORAGE_S3_SECRET_ACCESS_KEY=
MONITORING_STORAGE_S3_REGION=auto
MONITORING_STORAGE_S3_PATH_STYLE=true
```

<ParamField name="MONITORING_STORAGE_S3_BUCKET">
Object storage bucket where Monitoring payloads are stored.
</ParamField>
<ParamField name="MONITORING_STORAGE_S3_ENDPOINT">
S3-compatible endpoint (e.g., DigitalOcean Spaces, R2, MinIO, or AWS S3 endpoint).
</ParamField>
<ParamField name="MONITORING_STORAGE_S3_ACCESS_KEY_ID">
Access key used by Monitoring to write/read stored payloads.
</ParamField>
<ParamField name="MONITORING_STORAGE_S3_SECRET_ACCESS_KEY">
Secret key used with the access key. Store this as a secret.
</ParamField>
<ParamField name="MONITORING_STORAGE_S3_REGION" default="auto">
Region passed to the S3 client.
</ParamField>
<ParamField name="MONITORING_STORAGE_S3_PATH_STYLE" default="true">
When set to `true`, uses path-style object URLs instead of virtual-host style.
</ParamField>
