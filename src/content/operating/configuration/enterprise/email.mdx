Configure SMTP so Plane can send login alerts, password resets, and other Cloud notifications from your deployment.

If you do not already have an SMTP provider, services such as [Resend](https://resend.com), [SendGrid](https://sendgrid.com), or [Amazon SES](https://aws.amazon.com/ses/) can be used.

<Note>
SMTP is optional. You can skip these variables if you do not need email notifications yet.
</Note>

```dotenv .env wrap
EMAIL_PROVIDER=smtp
SMTP_HOST=
SMTP_PORT=587
SMTP_AUTH_USERNAME=
SMTP_AUTH_PASSWORD=
SMTP_TLS_MODE=auto
SMTP_SKIP_TLS_VERIFY=false
```

<ParamField name="EMAIL_PROVIDER">
Email transport Plane should use. Set this to `smtp`, or leave it unset so Plane uses SMTP when `SMTP_HOST` is configured.
</ParamField>
<ParamField name="SMTP_HOST">
Hostname of the SMTP server that sends mail for your deployment.
</ParamField>
<ParamField name="SMTP_PORT" default="587">
Port your SMTP server listens on. Use the value required by your provider.
</ParamField>
<ParamField name="SMTP_AUTH_USERNAME">
Username used for SMTP authentication. Some providers require a fixed username such as `resend`.
</ParamField>
<ParamField name="SMTP_AUTH_PASSWORD">
Password or API key used for SMTP authentication. Store this as a secret.
</ParamField>
<ParamField name="SMTP_TLS_MODE" default="auto">
TLS mode Plane uses for the SMTP connection. Use `auto` for STARTTLS-capable servers unless your provider requires another supported mode.
</ParamField>
<ParamField name="SMTP_SKIP_TLS_VERIFY" default="false">
Whether to skip TLS certificate verification. Use `false` in production.
</ParamField>
