Search is how you read ledgers, balances, transactions, and identities already stored in Blnk. Use the live ledger for product reads, the Data Lake for history, and Typesense when you need full-text search.

## Live records

Use the [Filter API](/search/db/filtering) when the answer has to come from the live ledger. A customer's transactions, balances in one currency, or identities that match a field are reads against the database your application writes to.

This is the path for product traffic. A field filter covers most of those reads, and it does not need a separate search service.

## Historical insights

Use the [Data Lake](/insights/lake) for historical insights and custom SQL. [Insights](/insights/overview) and the Data Lake API query a reporting copy, so that work stays off the ledger that is processing transactions.

Choose it for a period report, an investigation, or a question you would rather write in SQL. It is available on managed instances and with an Enterprise license.

## Advanced search

Blnk supports [Typesense](/search/typesense/introduction) for advanced search on the same collections. Use it for full-text matches, faceting, or a query that has outgrown a database filter.

Typesense stays off until you add it in your [data store configuration](/operating/configuration/data-stores#typesense-configuration). You do not need it for the Filter API.
