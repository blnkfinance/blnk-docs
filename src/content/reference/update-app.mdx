---
title: "Update app"
description: "Update a Custom App in the current organization."
method: "PATCH"
path: "/apps/{slug}"

---
Update a Custom App. Send only the fields you want to change. The `slug` stays the same when you change `name`.

An admin or a member can call this. Turning off `require_password_to_launch` needs a user session token and the account password.

<Authorization />

### Path

<ParamField path="slug" type="string" required>
  `slug` from [Get app](/reference/get-app).
</ParamField>

### Body

<ParamField body="name" type="string">
  Name shown in the Apps library. This does not change `slug`.
</ParamField>

<ParamField body="description" type="string">
  Short explanation of what the app does.
</ParamField>

<ParamField body="logo_url" type="string">
  Public URL of the app logo.
</ParamField>

<ParamField body="developer_name" type="string">
  Company, team, or person that built the app.
</ParamField>

<ParamField body="registration_callback_url" type="string">
  Absolute `http` or `https` URL Blnk calls on install and uninstall. It cannot include credentials, and it cannot target localhost or a private address.
</ParamField>

<ParamField body="portal_generator_url" type="string">
  Absolute `http` or `https` URL Blnk calls to open the app. Same address rules as `registration_callback_url`.
</ParamField>

<ParamField body="permissions" type="string[]">
  Scopes the app can be granted: `data:read`, `data:write`, `alerts:read`, and `alerts:write`. Omit this to leave the current scopes. Send a list to replace them.
</ParamField>

<ParamField body="is_private" type="boolean">
  `true` keeps the app in the current organization. `false` removes it from that library and clears `assigned_to`.
</ParamField>

<ParamField body="assigned_to" type="string[]">
  User ids allowed to launch the app, from [List team members](/reference/list-organization-members). Sending this replaces the current list, and an empty array means every member. The list is kept only when the app is private.
</ParamField>

<ParamField body="require_password_to_launch" type="boolean">
  Whether every [launch](/reference/launch-app) asks for the account password again. Turning this from `true` to `false` needs a session token, `password`, and `two_factor_code` when 2FA is on.
</ParamField>

<ParamField body="password" type="string">
  Account password of the signed-in user. Required when you set `require_password_to_launch` to `false`.
</ParamField>

<ParamField body="two_factor_code" type="string">
  2FA code. Required with `password` when 2FA is on for this user.
</ParamField>

### Response

A `200` response returns the updated app. The fields match [Get app](/reference/get-app).

<ResponseField name="app_id" type="string" required>
  Id of the app (`app_...`).
</ResponseField>

<ResponseField name="slug" type="string" required>
  Identifier of the app. Unchanged by this call.
</ResponseField>

<ResponseField name="name" type="string" required>
  Name shown in the Apps library.
</ResponseField>

<ResponseField name="permissions" type="string[]">
  Scopes the app can be granted.
</ResponseField>

<ResponseField name="assigned_to" type="string[]">
  User ids allowed to launch the app. Empty means every member.
</ResponseField>

<ResponseField name="require_password_to_launch" type="boolean" required>
  Whether a launch asks for the account password again.
</ResponseField>

<ResponseField name="updated_at" type="string" required>
  When the app was last updated.
</ResponseField>

<RequestExample>

```bash cURL
curl -X PATCH "https://api.cloud.blnkfinance.com/apps/stripe-sync" \
  -H "X-blnk-key: CLOUD_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "description": "Sync Stripe payments and payouts into the ledger."
  }'
```

</RequestExample>
