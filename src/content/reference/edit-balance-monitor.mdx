title: "Update balance monitor"
sidebarTitle: "Update monitor"
description: "Update the details of a balance monitor."
method: "PUT"
path: "/balance-monitors/{monitor_id}"
noindex: true
---
<Key />

From 0.15.9, a PUT changes only the fields you send. Every body field is optional, and a field you leave out keeps its stored value.

### Path

<ParamField path="monitor_id" type="string" required>
  The unique id of the balance monitor to update.
</ParamField>

### Body

<ParamField body="balance_id" type="string">
  Specifies the balance id of the ledger balance to be monitored.
</ParamField>

<ParamField body="condition" type="object">
  Defines the criteria for monitoring a specific balance type.
  <Expandable>
    <ParamField body="field" type="string">
      Specifies the balance type to be monitored. Every ledger balance has 6 balance types - `balance`, `inflight_balance`, `credit_balance`, `inflight_credit_balance`, `debit_balance`, and `inflight_debit_balance`.
    </ParamField>
    <ParamField body="operator" type="string">
      Comparison to apply: `>`, `<`, `>=`, `<=`, `=`, or `!=`. Any other value returns `400 GEN_VALIDATION_ERROR`.
    </ParamField>
    <ParamField body="value" type="number">
      Threshold in major units. `0` and fractions such as `100.50` are valid.
    </ParamField>
    <ParamField body="precision" type="number">
      Scale for `value`. Send it together with `value`. If you send it alone, it is ignored and the response includes `precision_unchanged`.
    </ParamField>
  </Expandable>
</ParamField>

<ParamField body="trigger" type="string">
  How you want the monitor to behave. `edge` notifies you once when the rule first matches, then stays quiet until the amount no longer matches. 
  
  `level` notifies you on every transaction that updates the balance while the rule still matches.
</ParamField>

<ParamField body="description" type="string">
  A brief explanation of the purpose of the monitor.
</ParamField>

### Response

<ResponseField name="message" type="string" required>
  Confirms the monitor was updated.
</ResponseField>

<ResponseField name="precision_unchanged" type="boolean">
  `true` when you sent `precision` without `value`. The stored precision and threshold were kept. Only included in that case.
</ResponseField>

<RequestExample>

```bash cURL
curl -X PUT "http://localhost:5001/balance-monitors/{monitor_id}" \
  -H "X-blnk-key: <api-key>" \
  -H "Content-Type: application/json" \
  -d '{
    "balance_id": "bln_0be360ca-86fe-457d-be43-daa3f966d8f0",
    "trigger": "level",
    "condition": {
      "field": "debit_balance",
      "operator": ">",
      "value": 1000,
      "precision": 100
    }
  }'
```

</RequestExample>

<ResponseExample>

```json 200 OK
{
  "message": "BalanceMonitor updated successfully"
}
```

```json 404 Not Found
{
  "error": "Monitor with ID 'mon_c5d9e2a1-7b4f-4a3c-9e8d-1f6a2b4c8d30' not found",
  "error_detail": {
    "code": "BAL_MONITOR_NOT_FOUND",
    "message": "Monitor with ID 'mon_c5d9e2a1-7b4f-4a3c-9e8d-1f6a2b4c8d30' not found"
  }
}
```

</ResponseExample>
