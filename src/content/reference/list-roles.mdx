List built-in and custom roles for the current organization. A built-in `role_id` looks like `system:admin`, and a custom `role_id` looks like `role_...`.

Use `role_id` to update or delete a role, and the identifier when you assign one.

<Authorization />

### Response

The response is a JSON array of roles.

<ResponseField name="role_id" type="string" required>
  Id of the role. Built-in roles look like `system:admin`. Custom roles look like `role_...`.
</ResponseField>

<ResponseField name="slug" type="string" required>
  Identifier of the role. Use it when you [Assign role](/reference/assign-role).
</ResponseField>

<ResponseField name="name" type="string">
  Display name of the role.
</ResponseField>

<ResponseField name="description" type="string">
  What the role is for.
</ResponseField>

<ResponseField name="permissions" type="string[]">
  Permissions on the role. See the [permission catalog](/access-control/rbac#permission-catalog).
</ResponseField>

<RequestExample>

```bash cURL
curl -X GET "https://api.cloud.blnkfinance.com/organizations/roles" \
  -H "X-blnk-key: CLOUD_API_KEY"
```

</RequestExample>

<ResponseExample>

```json 200 OK
[
  {
    "role_id": "system:admin",
    "slug": "admin",
    "name": "Admin"
  },
  {
    "role_id": "role_8f2c1a40-6b1e-4d3a-9c70-1e5a2b4d8f16",
    "slug": "finance-ops",
    "name": "Finance Ops",
    "description": "Read billing and ledger data",
    "permissions": ["billing.read", "data.read", "instances.read", "org.read"]
  }
]
```

</ResponseExample>
