Use `blnk.Transactions.bulkVoidInflight` to void multiple inflight transactions.

<Steps>
<Step title="Call the method">

<RequestExample>

```typescript Queued void
const response = await blnk.Transactions.bulkVoidInflight({
  transaction_ids: [
    'txn_11111111-1111-4111-8111-111111111111',
    'txn_22222222-2222-4222-8222-222222222222',
  ],
});
```

```typescript Synchronous void
const response = await blnk.Transactions.bulkVoidInflight({
  skip_queue: true,
  transaction_ids: [
    'txn_11111111-1111-4111-8111-111111111111',
    'txn_22222222-2222-4222-8222-222222222222',
  ],
});
```

```typescript Dry run {2}
const preview = await blnk.Transactions.bulkVoidInflight({
  dry_run: true,
  transaction_ids: [
    'txn_11111111-1111-4111-8111-111111111111',
    'txn_22222222-2222-4222-8222-222222222222',
  ],
});
```

</RequestExample>

<Tabs>

<Tab title="Synchronous void">

Pass `skip_queue: true` to process each void synchronously instead of queuing.

</Tab>

<Tab title="Dry run">

Preview every void without releasing any hold. Items are projected independently. See [Dry-run transactions](/transactions/dry-run).

| Field | Type | Description |
| :-- | :-- | :-- |
| `dry_run` | `true` | Return a `BulkTransactionPreview` without voiding. Holds stay in place. |

Pass `dry_run: true` inline, as shown above, to infer the preview response. If the request is declared separately, type it as `DryRun<BulkVoidInflightRequest>`.

</Tab>
</Tabs>

| Field | Type | Description |
| :-- | :-- | :-- |
| `transaction_ids` | `string[]` | Up to 100 inflight transaction IDs to void. |
| `skip_queue` | `boolean` | When `true`, process synchronously instead of queuing. |
</Step>

<Step title="Review per-item results">

On a posted batch, check `response.data.results` for each transaction's outcome. Failed items include a code and message without stopping the rest of the batch.

A dry run has no `succeeded` / `failed` counts. Check `would_apply` and `results`.

</Step>

| Field | Type | Description |
| :-- | :-- | :-- |
| `succeeded` | `number` | Number voided successfully. |
| `failed` | `number` | Number that failed. |
| `results` | `object[]` | Per-transaction outcome in request order. |
| `results[].status` | `string` | `succeeded` or `failed`. |
| `results[].code` | `string` | Failure code (for example `NOT_FOUND`, `ALREADY_COMMITTED`, `NOT_INFLIGHT`). |
| `results[].message` | `string` | Human-readable failure message. |
</Step>
